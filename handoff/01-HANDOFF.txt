■ 1. 목표와 사용자 요구
10개 추리·탐색 게임을 처음 방문한 사람이 설명 없이 진행할 수 있게 만드는 것이 목표입니다.
사용자는 메인 장면 사진의 분위기에는 비교적 만족하지만, 주변 UI·힌트·결말이
모든 테마에서 같은 네모 패널과 색상으로 반복되는 점을 계속 지적했습니다.
배경색만 바꾸는 수준으로 완료 처리하지 마세요. 테마마다 물건의 재질, 글꼴,
글씨 색, 배치, 힌트를 받는 방식, 직접 조작하는 장치를 구분해야 합니다.

중요한 요구:
- 10개 전부 확인. 첨부된 사례 몇 개만 고치고 전체 완료라고 말하지 않기.
- 흰 글씨/밝은 종이, 안 보이는 비활성 문구, 잘림, 긴 숫자의 어색한 줄바꿈 제거.
- 장면 속 실제 물건과 핫스폿 위치 일치. 이동 버튼은 이동임을 알 수 있게 배치.
- 풀지 않은 다음 구역은 선행 조건에 따라 잠겨 있어야 함.
- 기록의 우상단 뒤로 가기는 방 첫 화면이 아니라 바로 직전 물건 화면으로 복귀.
- 마지막 힌트는 실제 정답과 정확한 조작 순서·버튼명을 제공. 다시 추측시키지 않기.
- 스토리는 자연스러운 한국어와 구체적인 명칭. '상자 속 네 물건'처럼 오해되는
  제목, 추상적인 연결/기록 표현, 중복 문장, 불필요한 어려운 표현 재검토.
- 피드백은 방문자가 제출할 수 있지만 내용은 소유자만 열람.
- PC와 모바일 모두. 실제 휴대폰이 연결되지 않았으므로 실기기 확인으로 말하지 않기.
- 사용자에게 존댓말을 쓰고 검증한 범위와 미확인 사항을 구체적으로 보고.

■ 8. 로컬 개발과 주의점
검증 환경 Node v24.18.1, npm 11.16.0. package-lock.json을 보존.
cd mystery-site
npm ci
npm run build
node scripts/audit-playability-v64.cjs
node scripts/check-hint-entries-v77.cjs

npm run build는 scripts/build-v44.mjs → build-performance-v53.mjs를 실행합니다.
web/game-bundles 및 dist/client, dist/server/index.js, dist/.openai 등을 생성합니다.
web/*.html의 CSS/JS 순서가 중요합니다. 최신 finale-v79.css는 해당 4개 진입점의
마지막 수정 계층입니다. 생성된 dist 또는 game-bundles만 수정하면 다음 빌드에 사라집니다.

글꼴에 새로운 한글이 필요할 때(기존 완성 자산으로 빌드만 하면 Python 불필요):
python -m pip install fonttools brotli Pillow
python scripts/prepare-performance-assets.py --font-only
npm run build
원본 SUIT-Variable.woff2는 포함되어 있습니다.

design/BUILD.md의 'dist를 수정' 안내는 오래되어 현재에는 맞지 않습니다.
build-episodes, implement-*, refine-*, integrate-* 등 과거 생성/일회성 스크립트는
현재 문구/스타일을 덮어쓸 수 있습니다. 전체 스크립트를 일괄 실행하지 마세요.
오래된 검사도 예전 기대값을 가질 수 있습니다. 실패 이유를 읽고 현재 요구와 비교.

qa-tools/preview.mjs는 정적 프런트엔드 및 구성 요소 확인용입니다.
피드백 DB 쓰기/소유자 인증/운영 Worker 전체는 실행하지 않습니다.
node qa-tools/preview.mjs (압축 최상위에서 실행)
http://127.0.0.1:8790/audit79?case=garage
다른 case 값도 위 10개 ID를 사용합니다. 검사 도구가 URL을 /mechanics-preview로
바꾸면 새로고침 대신 /audit79?case=...를 다시 여세요. /audit79는 실제 빌드 CSS를 주입.
QA 버튼은 플레이를 건너뛰어 상태를 여는 도구입니다. 완주 검사의 대체물이 아닙니다.
