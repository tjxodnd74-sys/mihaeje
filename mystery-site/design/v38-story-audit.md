# v38 전체 이야기·자료 힌트 조사

이 문서는 현 v37 소스의 읽기 검토 결과다. 실제 브라우저 플레이 검증이나 Claude 검토 결과를 대신하지 않는다. 구현 파일과 배포 상태는 변경하지 않았다.

## 핵심 발견

1. `dist/hint-device.js:10`은 등록되지 않은 D 자료에 공통 3문장을 채운다. `episode.js:69`도 ID 몇 개만 특별 처리하고 나머지에 공통 fallback을 준다. 따라서 마지막 도움을 요청해도 예약표의 PIN·주소·현재 단계 답이 나오지 않는다. 첨부 JSON에 실제 10게임 **68개 D 자료 전체**의 3단계 문장을 작성했다. 셋째 도움은 명시적으로 요청한 경우에만 구체적 결과를 보여줘야 한다.
2. 힌트 목록의 P01·P02가 입구 잠금장치·안쪽 장치라는 공통 이름이다. P02 셋째 도움은 다시 S 코드를 찾으라고 해서 도움 요청의 동선을 늘린다. 현 장치의 실제 이름·S 코드로 바로 연결하거나 현 단계 도움과 통합하는 편이 맞다. D는 자료에 대한 설명, 현 퍼즐의 S는 현재 조작의 답이라는 구분이 필요하다.
3. `story-devices-v36.js`는 `theme.opening`의 긴 전체 공략을 **매 단계 narrative 앞에 붙인다**. 시작 안내만 줄여도 6개 단계에서 같은 전체 풀이 설명이 반복된다. 전체 공략을 제거하고 장치의 물리적 상태·해당 장치가 왜 필요한지만 한두 문장으로 남겨야 한다.
4. 실제 서사 결과는 대체로 인과가 맞으나, 자료의 제약을 미리 모두 설명하는 문장과 위에서 내려다본 정답 예제를 첫 화면에 많이 넣는다. 이것이 이해를 돕는 대신 시험 설명문처럼 만든다. 의뢰에는 미해결 질문 하나, 찾은 기록에는 관측 사실, 장치에는 조작 상태만 남기는 구성으로 분리해야 한다.
5. 고정 난이도에서 garage·laundry ★4와 radio ★5는 매 단계 2개 근거 선택, ★5는 반박 문장까지 반복한다. 이것은 난이도보다 반복 입력 부담을 높인다. 조작 자체의 단계·분기·독립 단서 수를 난이도로 삼고, 근거 선택이 필요한 핵심 결론에만 근거를 붙이는 방식이 더 자연스럽다.
6. 새 도입을 만들어도 `pet-home` 자료 rule의 사진 두 조각 맞추기, 각 테마 D 기본 도입과 `journeys-v37` opening의 도구 조합 지시가 남으면 다시 이전 방식으로 플레이어를 유도한다. **실제 도입 행동·배경의 남은 물체·기록 본문·힌트**가 같이 바뀌어야 한다.

## 자료 반환 경로의 실제 오류

- `studio.js:94` 힌트 설정의 `openRecord:inspect`는 S-D07 `portrait`, S-D09 `ending`을 그대로 전달한다. 실제 관찰 분기(`studio.js:60`)는 `photo`와 `portrait-back`이므로 portrait와 ending에서 빈 패널을 만들 수 있다. 이미 `records` 목록에는 `portrait:'photo', ending:'photo'` 매핑이 있고 이를 힌트에도 일관되게 적용하면 된다.
- `ohang.js:36` O-D07 `letter`는 `record('letter')`로 돌아간다. `text.letter`도 없고 record의 letter 전용 분기도 없으므로 빈 제목 패널로 돌아간다. 실제 완성한 편지의 `showEnding()` 또는 letter를 표시하는 상태별 본문으로 연결해야 한다.
- garage begin은 새 게임에서도 `openDoc('brief')`를 부르고 곧바로 read에 추가한다. studio initial/normalize은 시작하지 않아도 `read:['brief']`이다. 오행의 birth() 성공은 `read=['brief','symbols']`를 자동 입력한다. 따라서 `read.includes('brief')`만으로 ‘이야기를 읽고 나면 탐색 공개’ 조건을 만들면 새 게임부터 탐색이 열리는 문제가 생긴다. 별도의 실제 읽기 완료 ACK가 필요하다.

`design/v38-record-hints.json`의 `themes[theme].records[docId]`를 사용한다. `code`는 현 문서 배열 순서에 대응하며 배열 순서를 바꾸면 재매핑해야 한다. 68개 record 모두 정확히3개의 비어있지 않은 steps가 있다. 오행의 중괄호 placeholder는 현재 상태로 치환하며 아직 profile/choice가 없을 때 임의 생일·결말을 넣지 않는다. 자료가 잠겨 있으면 힌트도 그 자료를 발견/읽은 뒤만 요청할 수 있어야 한다. 셋째 자료 힌트는 마지막 수단이므로 반전 문장을 처음·둘째 도움에 올리지 않는다.

아파트 필름의 실제 그림과 네이티브 작업 수치, 각 잠긴 최종 기록은 소스에서 교차 확인했다. 신규 v38 도입에서 코드 잠금 자체가 제거되면 기존 입구 P 힌트는 없애고 새 행동의 도움으로 작성해야 한다. 이 파일은 기존 도구/START 체인을 정당화하기 위한 공략이 아니라 **실제 서사 자료의 뜻**을 전달하는 자료별 문장이다.
