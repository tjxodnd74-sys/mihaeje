# 데이터 보안(Data safety) 섹션 답 초안

플레이 콘솔 → 앱 콘텐츠 → 데이터 보안에 넣을 답입니다
근거 코드: `web/v2/engine.js`(진행 저장 · 「의견 남기기」 전송), `web/v2/feedback-config.js`(구글 설문지 주소), `web/v2/episodes/ohang.js`(생년월일 입력), 허브의 `beta-ui.js`·`audio-ui.js`·`background-music.js`
개인정보처리방침: `mystery-site/web/privacy.html` (배포 뒤 주소 https://mihaeje.com/privacy.html)

## 결론 먼저

- 「의견 남기기」 구글 설문지를 **연결하고 출시**하면 → 아래 '수집함' 답 (의견 글 · 선택 연락처 · 플레이 위치)
- 설문지를 **연결하지 않고 출시**하면(`feedback-config.js`의 `form`이 비어 있는 지금 상태) → 기기 밖으로 나가는 정보가 없으므로 **"사용자 데이터를 수집하거나 공유하지 않음"**
- 어느 쪽이든 '공유'는 없음, 광고 없음, 계정 없음

## 1. 데이터 수집 및 보안 (첫 질문들)

| 질문 | 답 | 이유 |
|---|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유하나요? | 예 (설문지 연결 시) / 아니요 (미연결 시) | 기기 밖으로 나가는 건 「의견 남기기」뿐 |
| 수집하는 데이터는 전송 중에 암호화되나요? | 예 | 구글 설문지 전송은 HTTPS (`fetch(cfg.form, …)`), 사이트도 HTTPS |
| 사용자가 데이터 삭제를 요청할 수 있나요? | 예 | 개인정보처리방침 8·11항의 이메일로 요청 (이메일 [사용자 확인 필요]) 계정이 없으므로 계정 삭제 주소는 해당 없음 |

## 2. 데이터 유형별 답 (설문지 연결 시)

| 데이터 유형 (콘솔 이름) | 수집 | 공유 | 일시적 처리 | 필수/선택 | 목적 |
|---|---|---|---|---|---|
| 앱 활동 → **기타 사용자 제작 콘텐츠** (의견 글) | 예 | 아니요 | 아니요 | 선택 (사용자가 보내기를 누를 때만) | 앱 기능 (오류 확인·고객 지원) |
| 앱 활동 → **앱 상호작용** (어느 편·장소·푼 장치 수) | 예 | 아니요 | 아니요 | 선택 (의견과 함께만 전송) | 앱 기능 (오류 확인) |
| 개인 정보 → **이메일 주소** (답장용 연락처 칸) | 예 | 아니요 | 아니요 | 선택 | 앱 기능 (고객 지원 답장) |
| 개인 정보 → **전화번호** | 예 (선택) | 아니요 | 아니요 | 선택 | 앱 기능 (고객 지원 답장) |

- 연락처 칸 안내문이 '답장 받을 이메일이나 연락처 (선택)'이라 전화번호를 적을 수도 있어서 전화번호도 넣었습니다 칸 문구를 '이메일 (선택)'로 바꾸면 전화번호 줄은 빼도 됩니다
- '공유 아니요'인 이유: 구글 설문지는 운영자를 대신해 저장해 주는 서비스 제공자라 구글 기준의 '공유(제3자 전송)'에 해당하지 않음

## 3. 신고하지 않는 것과 이유

| 정보 | 신고 안 함 | 이유 |
|---|---|---|
| 게임 진행 기록, 소리 설정, 첫 화면 의견 양식의 작성 중 내용 | 수집 아님 | 기기 저장공간(localStorage)에만 있고 전송되지 않음 → 구글 기준 '기기에서만 처리되는 데이터'는 신고 대상 아님 |
| 오행당 편 생년월일·태어난 시각 | 수집 아님 | 기기 안에서 계산(`vendor/lunar-1.7.7.js`, 앱 안 파일)하고, 날짜 원본은 저장도 안 함 계산 결과만 기기에 저장, 의견 전송에도 안 들어감 |
| 기기 ID, 광고 ID, 위치, 사진, 연락처 | 수집 아님 | 쓰는 코드 없음, 광고·분석·오류 수집 도구 없음, 쿠키 없음 |
| 사이트 호스팅(GitHub Pages)의 접속 기록 | 신고 안 함 (판단) | 페이지를 받을 때 GitHub가 IP 같은 일반 접속 기록을 남기지만 운영자가 받거나 쓰지 않음 앱이 화면 파일을 앱 안에 담아 두는 구조라면 이 부분도 해당 없음 개인정보처리방침 6항에는 적어 둠 |

## 4. 앱 구조에 따라 다시 볼 것

- 앱 포장 방식(앱 안에 파일을 담는지, 웹 주소를 띄우는지)과 넣는 라이브러리를 확정한 뒤, Firebase·크래시 수집 같은 SDK가 들어가면 그 SDK가 모으는 정보를 추가로 신고해야 함
- 첫 화면의 '베타 · 의견 남기기'(`beta-ui.js`)는 예전 서버 주소(`/api/feedback`)로 보내는 양식이라 지금 GitHub Pages·앱에서는 전송되지 않음 이 양식을 살려 다른 곳으로 보내게 되면 그 항목(테마·기기·평점 등)도 위 표에 더해야 함
